Marché : États-Unis (proxy US, fuseau US, langue en-US).
2. **Un téléphone = un personnage = tous ses comptes = une identité réseau.** Téléphones virtuels **GeeLark** (plan Base : ADB + API + RPA, 29,9 $/mois par téléphone en illimité) pilotés en ADB depuis le **Mac mini de Paris** qui héberge Ghost (serveur, scheduler, dashboard, MCP), le module farm et nos workflows. Nathan est en Thaïlande, accès SSH. Comptes par personnage : Instagram + TikTok (versions SFW, pointent vers ofmai.ai) ; X (18+) et Reddit (NSFW selon sub, pointent vers hotofmai.ai / Fanvue). Telegram est une autre machine (M2), hors périmètre, mais le modèle de comptes doit pouvoir l'accueillir.
3. **Réseau** : proxies **IPRoyal** (compte existant, format déjà accepté par `lib/ingest/instagram-proxy.ts`). Par téléphone : une IP **statique résidentielle ISP US** (2,40 $/IP/mois, le « domicile », jamais changée) pour la chauffe, le scroll, les réponses, l'essentiel des posts ; un **mobile en session collante** (5,20 $/Go) même État, pour la création du compte, les vérifications et une partie des sessions de post, une à deux fois par jour, bascule entre deux sessions avec pause, jamais au milieu d'une action. GPS, fuseau, langue, région de store alignés sur le proxy dans GeeLark. Un téléphone tourne aussi en « observateur » (profil séparé, autre proxy) pour les canaris de shadowban en déconnecté.
4. **Comptes : créés, jamais achetés** (règle définitive). Email par personnage créé sur son téléphone. Inscription par email sur IG, TikTok, X, Reddit ; quand une vérification SMS ou un captcha apparaît, le **checkpoint** Ghost suspend le run et un humain (Nathan ou l'assistant) fournit le code : prévoir la procédure et le pool de numéros (réels, jamais virtuels ; à définir avec Nathan, ex. un téléphone physique au bureau de Paris avec quelques SIM).
5. **Chauffe** : la politique existe dans le fork (`policy.py` : phases consume 1-3 j → light 4-7 → network 8-14 → cruise 15+, +3 jours par phase sur TikTok ; caps par action et ratios like/vue ≤ 15 %, follow/visite ≤ 30 % ; 2-4 sessions/jour dans des fenêtres dérivantes, jamais 01-07 h locale ; un jour de repos par semaine ; budget quotidien 40-100 % des caps, déterministe par (compte, jour)). `docs/social/warming-policy.md` doit être la source de vérité **cohérente avec le code** (vérifier les nombres dans `policy.py`), et compléter ce que le code ne dit pas : pools de commentaires par persona, détours (recherche hashtag de niche, stories), « poser le téléphone », et le passage en `api_mode`.
6. **Publication** : Instagram sur l'appareil (workflow `post_video` existe, Reel depuis la galerie ; l'API Graph est exclue : compte Business + revue Meta 2-4 semaines). TikTok : sur l'appareil pendant la chauffe, puis `api_mode` = publication par l'API officielle TikTok Content Posting via le MCP Higgsfield (`tiktok_connect`, `tiktok_prepare_publish`, `tiktok_publish`, 13 posts/jour max, photos JPEG/WebP, vidéos MP4 9:16, toggle AIGC obligatoire) tandis que l'appareil ne fait plus que de la consommation légère. X et Reddit : chauffe et engagement sur l'appareil (apps), publication par leurs API officielles depuis le Mac mini **à travers la même IP statique du personnage** ; à trancher et justifier dans la doc : app vs API pour chaque geste.
7. **Où pointent les liens** (décision de stratégie) : Instagram et TikTok → link-in-bio avec Fanvue en premier (page créatrice IA du personnage, badge « AI creator », pièce d'identité de l'opérateur), mention « AI » dans la bio, et **comment-to-DM** via l'API officielle Meta (ManyChat ou équivalent, 200 DM/h max, réponse uniquement à une action de l'utilisateur) : un commentaire contenant « real », « how », « ai », « tool » déclenche un DM « elle est 100 % IA, faite sur OFMAI, 15 crédits offerts ». Reddit → tri par sub : subs de créateurs/art IA → page OFMAI du personnage « crée la même » ; subs de fans → Fanvue. X → Fanvue + mention OFMAI. Un **compte de marque OFMAI** par plateforme publie le making-of et les résultats (hors périmètre de la chauffe, mais à prévoir dans le modèle).
8. **Contenu** : la génération reste **côté OFMAI** (moteurs, Soul/LoRA, S3, QA) ; la ferme ne génère jamais, elle **publie** ce qu'OFMAI lui met en file (pont, décision 9). **Source d'inspiration n° 1 : le radar** — les reels et les **carrousels** (`ScrapedPost.mediaType` image | video, `outlierScore`, médias sur R2) des comptes de la niche du personnage, reproduits avec le personnage via le pipeline de réplication existant (`lib/ingest/replication-batch.ts`, bouton « Reproduire avec mon character »). Les prompts Foxy et les hooks pattern-interruption ne sont qu'un complément quand le radar ne donne rien. Banque `ContentAsset` (clés S3, jamais d'URL), contrôle qualité existant (Rekognition CompareFaces, vision anatomie, hash perceptuel), 3 générés pour 1 gardé, re-rendu par plateforme pour un hash unique, filigrane, légendes par persona, agent conformité. Volume cible en cruise : 6 assets/jour/personnage.
9. **Pont OFMAI ↔ ferme** (marqué « not done yet » dans FARM.md) : file de contenu (clés S3 + légendes par personnage), pools de commentaires par persona, événements retour (posté, id du post, métriques à J+1, signaux santé), authentification par secret, idempotence, tables des deux côtés (Prisma côté OFMAI, SQLAlchemy `farm_*` côté fork).
10. **Santé** : signaux écran existants (`health.py` : action block, vérification, déconnecté, suspendu, zéro portée) ; ajouter les **canaris de shadowban** (depuis le profil observateur déconnecté : post visible dans le feed « new » du sub / recherche X / vues TikTok à 24 h vs référence) ; règles : un signal → pause 48 h du compte ; deux comptes rouges en 48 h sur une plateforme → pause de la plateforme ; jamais changer l'IP statique ; escalade humaine par Discord ; `accounts clear-health` par un humain.
11. **Mesure** : UTM `utm_source` (instagram, tiktok, x, reddit) × `utm_content=<personnage>`, vérité en prod (`User.signupSource` × `Subscription`), PostHog pour le funnel, rapport Discord quotidien ; seuils de décision J4 / J7 / J14 (cf. plan Machine ×10 : Reddit < 1 500 vues médianes/post ou 2 retraits sur un sub → changer de subs ; X < 500 impressions/post après 100 posts → 2/jour ; 3 comptes bannis en 48 h sur une plateforme → plateforme coupée).
12. **Règles absolues** : aucun clone d'une vraie personne sans ses photos uploadées par elle ; personnages synthétiques ; divulgation IA partout où la plateforme l'exige (toggle AIGC TikTok, mention IA en bio, badge Fanvue, `#AI`) ; SFW seul sur IG/TikTok/Meta (ofmai.ai), 18+ sur Reddit/X (hotofmai.ai) ; aucun nom de fournisseur tiers visible (Higgsfield, Seedance, WaveSpeed, Modal, GeeLark, IPRoyal… n'apparaissent jamais dans un texte publié) ; jamais « même visage » ; quotas dans le ledger, pas dans les prompts ; pas d'automatisation de follow en masse (incident @potter_society sur X : arrêt au premier 429).

## Deux repos, une base par repo
- **OFMAI** (plateforme, Postgres prod + S3) : personnages, génération, banque `ContentAsset`, pages publiques, endpoints du pont, attribution. Les workflows de contenu (`growth-content-army.js`) vivent dans OFMAI parce qu'ils appellent ses moteurs.
- **ofmai-farm** (Mac mini, SQLite de Ghost + tables `farm_*`) : téléphones, comptes, chauffe, publication, santé. Les workflows de ferme vivent dans le fork.
- Le Mac mini héberge les deux clones ; la ferme parle à OFMAI **par l'API du pont** (`https://ofmai.ai/api/farm/...`), jamais directement à la base de prod. Aucune troisième base.
